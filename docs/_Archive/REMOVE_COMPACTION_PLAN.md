# Context Compaction Removal Assessment & Plan

This document outlines the assessment and exact steps required to cleanly and completely remove the context compaction functionality from the LLM Gateway. Since the core functionality (the `ContextManager` in `src/context/strategy.js` and `_handleContextCompaction` in `src/core/model-router.js`) has already been deprecated and deleted, the remaining work is primarily structural cleanup, schema validation removal, and documentation cleanup.

## Current State

The gateway evaluates token bounds for requests natively but no longer forcibly compacts messages by recursively calling an LLM. However, the remnants of the `compaction` parameter remain baked into:
- The global config schema
- The `ModelRegistry` properties
- The system events dispatcher (SSE event system)
- The documentation
- Tests that explicitly mock or test the `compaction` config

## Removal Plan

### 1. Configuration & Schema Cleanups
**Target Files:** `config.json`, `config.example.json`, `src/core/config-schema.js`
- **Action:** Remove the `"compaction": { ... }` object entirely from the default configurations.
- **Action:** Delete the `// Compaction config` validation block starting at `if (config.compaction) {` in `src/core/config-schema.js`. This guarantees the gateway no longer attempts strict typing on a removed feature.

### 2. Registry Unbinding
**Target File:** `src/core/model-registry.js`
- **Action:** Remove `compaction: resolvedConfig.compaction || { enabled: false }` from the `this.globalConfig` initialization block.
- **Action:** Delete the `getCompactionConfig()` method completely from the `ModelRegistry` class.

### 3. Events & Route Pruning
**Target Files:** `src/core/events.js`, `src/routes/events.js`, `src/routes/chat.js`
- **Action:** Delete `COMPACTION_STARTED` and `COMPACTION_COMPLETED` from the `EVENT_TYPES` enumeration.
- **Action:** Remove the bindings for `compactionStartedHandler` and `compactionCompletedHandler` in the SSE Events router `src/routes/events.js`.
- **Action:** Remove the `// Handle async requests with compaction` comment in `src/routes/chat.js` (line 81) as the async ticketing system is no longer dedicated to running slow compaction chains.

### 4. Test Suite Refactoring
**Target Files:** `tests/new-core.test.js`, `tests/router.v2.test.js`
- **Action:** Remove the `compaction` objects from test mock config environments (e.g. line 64 in `new-core.test.js`).
- **Action:** Remove `expect(registry.getCompactionConfig().enabled).to.be.true;` assertion in `new-core.test.js`.
- **Action:** Delete the `describe('Context Compaction Config', ...)` suite inside `tests/router.v2.test.js`.

### 5. Documentation Scrubbing
**Target Files:** `README.md`, `AGENTS.md`, `.github/copilot-instructions.md`, `documentation/api_rest.md`
- **Action:** Remove all architectural mentions declaring the gateway "supports three compaction strategies" (`truncate`, `compress`, `rolling`).
- **Action:** Remove references to `minTokensToCompact`.
- **Action:** Remove mentions of `event: compaction.progress`, `event: compaction.start`, and `event: compaction.complete` behavior from the REST WebSocket and Events documentation, clarifying that large context truncation isn't done silently by default anymore.

## Summary

No core routing logic will break due to this removal, as token estimation `_estimateMessagesTokens` is functionally separate from `compaction` and still cleanly annotates context telemetry passed back to the WebSocket layer or HTTP clients. Applying this plan will formally strip the technical debt generated by the v1 Context Compaction feature.
